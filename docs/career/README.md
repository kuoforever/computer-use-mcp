# Career and learning hub

> **Status: current navigation and maintenance contract, 2026-08-10.**
> Shared teaching protocol version: `1`.

This directory keeps two related but different kinds of material:

| Category | Document | Owns |
| --- | --- | --- |
| Job-application evidence | [Resume evidence](resume/) | One Markdown file per candidate highlight, plus JD selection and claim-limit indexes |
| Collaboration method | [Teaching collaboration](teaching/) | Separate protocol, evidence-discipline, and interview-translation modules |

## Source hierarchy

These pages are derived views, not new project truth:

1. [Project status](../../PROJECT_STATUS.md) owns sequencing and closure state.
2. [Capability status](../CAPABILITY_STATUS.md) owns current capability and
   evidence levels.
3. Contract and dated evidence documents own exact behavior and retained runs.
4. Files under `resume/` may shorten those facts for job applications, but
   they may not promote or widen them.

Repository evidence proves what the project did. It does not by itself prove
which parts one person designed or implemented. Confirm personal ownership
before using any candidate bullet.

## Maintenance rules

- Keep the two categories separate: career evidence records durable material;
  teaching happens in conversation and does not create a second learning
  tracker.
- Update a candidate bullet only after its owner/evidence documents change.
- Keep `Offline`, `Provider`, `Desktop`, `Application`, and `Release` evidence
  distinct.
- Preserve negative results and exclusions; they are useful interview evidence
  of engineering judgment.
- When the shared teaching protocol changes, update the protocol version in all
  participating project repositories together.
