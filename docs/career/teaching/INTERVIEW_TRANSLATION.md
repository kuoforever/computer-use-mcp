# Interview translation

> **Status: current module of teaching protocol v1.**

Use six parts instead of reciting a feature list:

1. **Problem:** what failure or user need existed?
2. **Constraint:** what authority, safety, platform, or evidence boundary applied?
3. **Decision:** what design was chosen and what alternative was rejected?
4. **Implementation:** which contracts, states, or components changed?
5. **Verification:** what deterministic and real-surface evidence passed?
6. **Limit:** what remains unverified, and what is the next honest gate?

Useful follow-up questions include:

- Why was this invariant necessary?
- What failure window does the state machine model?
- Why did you choose fail-closed behavior?
- How did you distinguish mock coverage from real-system evidence?
- Which simpler alternative was rejected, and why?
- What result would falsify the current conclusion?

The agent may inspect, implement, test, explain, and propose wording. The user
owns product intent, personal-contribution claims, operator observations,
credentials, external accounts, and final job-application choices.
